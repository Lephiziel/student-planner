# Test Cases — Student Planner

Документ описывает основные тест-кейсы для проверки функциональности приложения. Тесты сгруппированы по модулям и могут выполняться через Postman/Insomnia (backend) и вручную через браузер (frontend).

Обозначения:
- **Pre** — предусловие
- **Steps** — шаги выполнения
- **Expected** — ожидаемый результат

---

## 1. Авторизация

### TC-1.1 — Успешная регистрация
**Steps:** `POST /api/auth/register` с валидными `name`, `email`, `password` (≥8 символов)
**Expected:** код `201`, в ответе `id`, `email`, `name`, поле `password_hash` отсутствует

### TC-1.2 — Повторная регистрация с тем же email
**Pre:** пользователь с email уже существует
**Steps:** `POST /api/auth/register` с тем же email
**Expected:** код `409`, сообщение `"email already taken"`

### TC-1.3 — Регистрация с коротким паролем
**Steps:** `POST /api/auth/register` с паролем короче 8 символов
**Expected:** код `400`

### TC-1.4 — Регистрация без email
**Steps:** `POST /api/auth/register` без поля `email`
**Expected:** код `400`

### TC-1.5 — Успешный вход
**Pre:** пользователь зарегистрирован
**Steps:** `POST /api/auth/login` с верными `email`/`password`
**Expected:** код `200`, в ответе `access_token` и `refresh_token`

### TC-1.6 — Вход с неверным паролем
**Steps:** `POST /api/auth/login` с верным email, неверным паролем
**Expected:** код `401`, сообщение `"invalid credentials"`

### TC-1.7 — Вход несуществующего пользователя
**Steps:** `POST /api/auth/login` с email которого нет в системе
**Expected:** код `401`, сообщение `"invalid credentials"`

### TC-1.8 — Обновление access-токена
**Pre:** есть валидный `refresh_token`
**Steps:** `POST /api/auth/refresh` с этим токеном
**Expected:** код `200`, новый `access_token`

### TC-1.9 — Refresh с невалидным токеном
**Steps:** `POST /api/auth/refresh` со случайной строкой вместо токена
**Expected:** код `401`

### TC-1.10 — Доступ к защищённому маршруту без токена
**Steps:** `GET /api/users/me` без заголовка `Authorization`
**Expected:** код `401`

### TC-1.11 — Доступ с просроченным токеном
**Pre:** access-токен истёк (>15 мин)
**Steps:** любой защищённый запрос с этим токеном
**Expected:** код `401`

## 3. Предметы

### TC-3.1 — Создание предмета
**Steps:** `POST /api/subjects/` с `name` и `color`
**Expected:** код `201`, предмет создан, привязан к текущему пользователю

### TC-3.2 — Создание предмета без названия
**Steps:** `POST /api/subjects/` без поля `name`
**Expected:** код `400`

### TC-3.3 — Получение списка предметов
**Pre:** у пользователя есть предметы
**Steps:** `GET /api/subjects/`
**Expected:** код `200`, возвращаются только предметы текущего пользователя

### TC-3.4 — Изоляция предметов между пользователями
**Pre:** пользователь A создал предмет, пользователь B авторизован
**Steps:** `GET /api/subjects/` от имени B
**Expected:** предмет пользователя A отсутствует в списке

### TC-3.5 — Редактирование предмета
**Pre:** предмет создан
**Steps:** `PUT /api/subjects/:id` с новым `name`/`color`
**Expected:** код `200`, данные обновлены

### TC-3.6 — Редактирование чужого предмета
**Pre:** предмет принадлежит пользователю A, запрос от B
**Steps:** `PUT /api/subjects/:id` от имени B
**Expected:** код `404`

### TC-3.7 — Удаление предмета
**Steps:** `DELETE /api/subjects/:id`
**Expected:** код `200`, `{"message":"deleted"}`, предмет больше не возвращается в списке

### TC-3.8 — Удаление чужого предмета
**Expected:** код `404`

### TC-3.9 — Статистика по предметам — пустой предмет
**Pre:** создан предмет без задач
**Steps:** `GET /api/subjects/stats`
**Expected:** `total_tasks: 0`, `done_tasks: 0` для этого предмета

### TC-3.10 — Статистика по предметам — с задачами
**Pre:** у предмета 3 задачи, 1 выполнена
**Steps:** `GET /api/subjects/stats`
**Expected:** `total_tasks: 3`, `done_tasks: 1`

## 4. Задачи

### TC-4.1 — Создание задачи без предмета
**Steps:** `POST /api/tasks/` без `subject_id`, с обязательными полями
**Expected:** код `201`, `subject_id` равен `null`

### TC-4.2 — Создание задачи с предметом
**Pre:** предмет создан
**Steps:** `POST /api/tasks/` с `subject_id` существующего предмета
**Expected:** код `201`, задача привязана к предмету

### TC-4.3 — Создание задачи с невалидным приоритетом
**Steps:** `POST /api/tasks/` с `priority: "urgent"`
**Expected:** код `400`

### TC-4.4 — Создание задачи без названия
**Steps:** `POST /api/tasks/` без `title`
**Expected:** код `400`

### TC-4.5 — Получение списка задач

**Steps:** `GET /api/tasks/`
**Expected:** код `200`, только задачи текущего пользователя

### TC-4.6 — Фильтр по статусу
**Pre:** есть задачи с разными статусами
**Steps:** `GET /api/tasks/?status=done`
**Expected:** возвращаются только задачи со статусом `done`

### TC-4.7 — Фильтр по приоритету
**Steps:** `GET /api/tasks/?priority=high`
**Expected:** возвращаются только задачи с приоритетом `high`

### TC-4.8 — Фильтр по предмету
**Steps:** `GET /api/tasks/?subject_id=1`
**Expected:** возвращаются только задачи этого предмета

### TC-4.9 — Поиск по названию
**Pre:** есть задача с названием "Сделать лабу по матеше"
**Steps:** `GET /api/tasks/?search=матеш`
**Expected:** задача найдена (регистронезависимый поиск)

### TC-4.10 — Поиск без совпадений
**Steps:** `GET /api/tasks/?search=несуществующийтекст123`
**Expected:** код `200`, пустой массив

### TC-4.11 — Фильтр по диапазону дат
**Pre:** есть задачи с разными `due_date`
**Steps:** `GET /api/tasks/?due_from=2026-06-01&due_to=2026-06-30`
**Expected:** возвращаются только задачи с дедлайном в этом диапазоне

### TC-4.12 — Комбинация фильтров
**Steps:** `GET /api/tasks/?status=todo&priority=high&search=лаб`
**Expected:** применяются все фильтры одновременно

### TC-4.13 — Обновление задачи
**Pre:** задача создана
**Steps:** `PUT /api/tasks/:id` с новыми данными
**Expected:** код `200`, поля обновлены

### TC-4.14 — Обновление чужой задачи
**Expected:** код `404`

### TC-4.15 — Изменение статуса через PATCH
**Steps:** `PATCH /api/tasks/:id/status` с `{"status":"done"}`
**Expected:** код `200`, `{"message":"updated"}`, статус задачи изменён

### TC-4.16 — Изменение статуса с невалидным значением
**Steps:** `PATCH /api/tasks/:id/status` с `{"status":"unknown"}`
**Expected:** код `400`

### TC-4.17 — Удаление задачи
**Steps:** `DELETE /api/tasks/:id`
**Expected:** код `200`, `{"message":"deleted"}`, задача больше не в списке

### TC-4.18 — Удаление чужой задачи
**Expected:** код `404`

### TC-4.19 — Статистика по задачам
**Pre:** у пользователя 10 задач: 4 done, 3 in_progress, 2 todo, 1 просрочена
**Steps:** `GET /api/tasks/stats`
**Expected:** `total: 10, done: 4, in_progress: 3, todo: 2, overdue: 1`

## 6. Frontend — UI тесты

### TC-6.1 — Регистрация через форму
**Steps:** открыть `/register`, заполнить форму валидными данными, отправить
**Expected:** редирект на `/login`

### TC-6.2 — Вход через форму
**Steps:** открыть `/login`, ввести данные, отправить
**Expected:** редирект на `/dashboard`, токены сохранены в `localStorage`

### TC-6.3 — Защита маршрутов
**Steps:** очистить `localStorage`, открыть `/dashboard` напрямую
**Expected:** редирект на `/login`

### TC-6.4 — Автообновление токена
**Pre:** access-токен истёк, refresh-токен валиден
**Steps:** выполнить любое действие требующее запрос к API (например открыть `/tasks`)
**Expected:** запрос автоматически повторяется с новым токеном, пользователь не разлогинен

### TC-6.5 — Перезагрузка страницы после логина
**Steps:** войти, перезагрузить страницу (F5)
**Expected:** пользователь остаётся авторизован

### TC-6.6 — Создание предмета через UI
**Steps:** `/subjects` → "+ Добавить" → заполнить название и цвет → "Создать"
**Expected:** предмет появляется в списке с выбранным цветом

### TC-6.7 — Создание задачи через UI
**Steps:** `/tasks` → "+ Новая задача" → заполнить форму → "Создать"
**Expected:** задача появляется в списке с указанными полями

### TC-6.8 — Изменение статуса задачи через выпадающий список
**Steps:** на странице `/tasks` изменить статус задачи через select
**Expected:** статус обновляется без перезагрузки страницы, badge меняется

### TC-6.9 — Поиск задач
**Steps:** ввести текст в поле поиска на `/tasks`
**Expected:** список обновляется через ~400мс (debounce), отображаются только подходящие задачи

### TC-6.10 — Фильтрация задач
**Steps:** выбрать значения в фильтрах статус/приоритет/предмет
**Expected:** список обновляется согласно фильтрам, кнопка "Сброс" появляется и очищает фильтры

### TC-6.11 — Добавление самооценки
**Steps:** на `/tasks` нажать ★ у задачи, ввести оценку и комментарий, "Добавить"
**Expected:** звёзды и комментарий отображаются у задачи

### TC-6.12 — Редактирование самооценки
**Pre:** у задачи уже есть самооценка
**Steps:** нажать ★, изменить значение, "Сохранить"
**Expected:** значение обновляется

### TC-6.13 — Удаление самооценки
**Steps:** нажать ★ у задачи с самооценкой, "Удалить самооценку"
**Expected:** звёзды пропадают, панель закрывается

### TC-6.14 — Календарь — отображение задач
**Pre:** есть задачи с `due_date` в текущем месяце
**Steps:** открыть `/calendar`
**Expected:** задачи отображаются на соответствующих датах с цветом предмета

### TC-6.15 — Календарь — просроченные задачи
**Pre:** есть задача с `due_date` в прошлом и статусом не `done`
**Steps:** открыть `/calendar`
**Expected:** задача отображается красным цветом

### TC-6.16 — Календарь — клик по задаче
**Steps:** кликнуть на задачу в календаре
**Expected:** открывается модальное окно с деталями (статус, приоритет, дедлайн, описание)

### TC-6.17 — Календарь — переключение месяцев
**Steps:** нажать "next"/"prev" в календаре
**Expected:** подгружаются задачи нового месяца

### TC-6.18 — Дашборд — статистика
**Pre:** есть задачи в разных статусах
**Steps:** открыть `/dashboard`
**Expected:** карточки "Всего/Выполнено/В работе/Просрочено" показывают корректные числа, прогресс-бар соответствует процентам

### TC-6.19 — Предметы — прогресс-бар
**Pre:** у предмета есть задачи, часть выполнена
**Steps:** открыть `/subjects`
**Expected:** отображается "X/Y задач" и прогресс-бар с правильным процентом

### TC-6.20 — Уведомления о дедлайне
**Pre:** разрешены уведомления браузера, есть задача с дедлайном через 1–24 часа
**Steps:** подождать до 60 секунд
**Expected:** появляется браузерное уведомление с названием задачи и датой дедлайна; повторно не показывается

### TC-6.21 — Выход из системы
**Steps:** нажать "Выйти"
**Expected:** токены удалены из `localStorage`, редирект на `/login`

### TC-6.22 — Адаптивность — мобильный экран
**Steps:** открыть приложение на экране ≤720px (или DevTools Responsive Mode)
**Expected:** навбар компактный, карточки статистики в 2 колонки, карточки задач в столбик, формы одноколоночные, нет горизонтального скролла страницы
